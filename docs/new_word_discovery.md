# 新词发现 (New Word Discovery)

## 定位声明

当前新词发现模块采用**零样本统计方法**，定位为**"建议引擎"**而非"自动决策"。

- ✅ 适合：领域术语发现、交互式词典构建、零样本NER增强
- ❌ 不适合：生产级精度要求、无人工审核的自动化流程

---

## 三种模式

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **关闭** | 不执行新词发现 | 快速分析、已知领域 |
| **仅发现** | 发现候选词，返回但不应用 | 人工审核、学习领域术语 |
| **强化模式** | 发现候选词→自动加入词典→重新分析 | 信任算法、需要快速迭代 |

### 模式选择建议

- **首次接触新领域**：使用"仅发现"，审核候选词质量
- **熟悉领域**：使用"强化模式"，自动优化分词
- **生产环境**：建议"仅发现" + 人工审核后手动加入词典

---

## 算法组成

### 统计引擎

| 算法 | 作用 | 参考 |
|------|------|------|
| PMI (逐点互信息) | 衡量字符共现强度 | Sun Maosong et al. |
| LLR (对数似然比) | 检验是否显著超过随机期望 | Duan et al. |
| 左右熵 | 衡量边界稳定性 | HanLP 1.x |
| 内聚度 | 内部结合强度 | 自定义 |

### 辅助引擎

| 引擎 | 作用 |
|------|------|
| MTL启发式 | 从HanLP分词结果中发现应合并的序列 |
| ConvSeg对比 | 第二意见：与粗分tokenizer对比 |

## 局限性

### 文本长度要求

| 文本长度 | 推荐模式 | 说明 |
|---------|---------|------|
| < 50字 | MTL启发式为主 | 统计信息不足 |
| 50-200字 | PMI+LLR辅助 | 自适应降低阈值 |
| > 200字 | 完整统计方法 | 效果最佳 |

### 已知限制

1. **统计方法固有缺陷**：短文本信息不足，候选质量下降
2. **无训练数据**：无法学习领域特定的分词模式
3. **POS覆盖有限**：当前只合并名词/形容词/动词，遗漏其他词性

## API 参考

### 端点

| 端点 | 说明 |
|------|------|
| `POST /analyze?discover=true` | 分析+发现候选词 |
| `POST /analyze?enhance=true` | 分析+发现+自动应用 |
| `POST /analyze/discover` | 仅发现候选词 |

### 请求示例

```bash
# 仅发现
curl -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"text":"碳钢是钢的一种，具有高强度。","discover":true}'

# 强化模式
curl -X POST http://localhost:8000/analyze \
  -H "Content-Type: application/json" \
  -d '{"text":"碳钢是钢的一种，具有高强度。","enhance":true}'
```

### 响应示例

```json
{
  "true_new_words": ["高强度"],
  "content": {
    "tokens": [...],
    "entities": [...],
    "relations": [...]
  }
}
